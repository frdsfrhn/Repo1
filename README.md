# PropertyMate

A Flutter + Firebase CRM for property agents: a lead dashboard, voice-note
capture with AI-cleaned transcripts, phone-number login, and a
subscription paywall — built to the MVP scope in the original
requirements checklist.

## What's here vs. what you still need to generate

This repo was built in an environment **without the Flutter SDK
installed**, so it contains the full application source — every Dart
file, the Firestore/Storage security rules, and the Cloud Functions
backend — but **not** the native `android/`, `ios/`, or `web/` platform
folders. Those are machine-generated by the Flutter tool itself and are
safer to generate on your machine than to hand-write. Follow the setup
below; the first two steps produce them.

Nothing here has been run through `flutter analyze`, `flutter pub get`,
or `flutter build` — do that as your first step and expect to fix minor
issues (package version pins may need adjusting to whatever's current
when you install, since I built this without the SDK available to
verify against).

## Prerequisites

- Flutter SDK (stable channel) — <https://flutter.dev/docs/get-started/install>
- A Firebase project with the **Blaze (pay-as-you-go)** plan — required
  for Cloud Functions to call external APIs (Speech-to-Text, Anthropic)
- Node.js 20+ (for Cloud Functions)
- A RevenueCat account, with Apple/Google Play in-app products configured
- An Anthropic API key (for transcript cleanup)
- Xcode (iOS) and/or Android Studio (Android), for device testing

## 1. Generate native scaffolding

From the repo root:

```bash
flutter create --org com.yourcompany --project-name property_agent_app .
```

This fills in `android/`, `ios/`, and (if you want it) `web/` around the
existing `lib/` — it will not overwrite `lib/`, `pubspec.yaml`, or this
README as long as you answer "no" if prompted to overwrite existing
files, but **do** let it create the platform folders.

```bash
flutter pub get
```

## 2. Firebase project setup

```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli

firebase login
firebase projects:create   # or use an existing project
flutterfire configure      # generates lib/firebase_options.dart and
                            # registers your Android/iOS/web apps
```

In the [Firebase console](https://console.firebase.google.com):

1. **Authentication → Sign-in method** → enable **Phone**.
2. **Firestore Database** → create in production mode, pick a region
   close to your users (e.g. `asia-southeast1` for Malaysia — this also
   needs to match the `region` set in `functions/src/index.ts`).
3. **Storage** → create a default bucket, same region.
4. **Upgrade to the Blaze plan** (Functions calling external APIs
   requires it).

Deploy security rules and indexes:

```bash
firebase deploy --only firestore:rules,firestore:indexes,storage:rules
```

## 3. Cloud Functions

```bash
cd functions
npm install
```

Set the two secrets Functions need (you'll be prompted for the values —
paste them in, nothing is echoed):

```bash
firebase functions:secrets:set ANTHROPIC_API_KEY
firebase functions:secrets:set REVENUECAT_WEBHOOK_AUTH
```

`REVENUECAT_WEBHOOK_AUTH` is a string you make up yourself (e.g. a random
UUID) — you'll paste the same value into RevenueCat's webhook config in
step 5, as an `Authorization` header value.

Also enable the **Cloud Speech-to-Text API** for your GCP project (same
project as Firebase): [console.cloud.google.com → APIs & Services →
enable "Cloud Speech-to-Text API"](https://console.cloud.google.com/apis/library/speech.googleapis.com).

Deploy:

```bash
npm run build
cd ..
firebase deploy --only functions
```

Note the deployed URL for `revenuecatWebhook` (printed at the end of
deploy, or visible in the Firebase console under Functions) — you need it
for step 5.

## 4. Microphone permission strings

Required by both app stores — the OS shows this text the first time the
app asks for microphone access.

**`ios/Runner/Info.plist`** — add:

```xml
<key>NSMicrophoneUsageDescription</key>
<string>We need your microphone to record voice notes about your leads, which are transcribed into text.</string>
```

**`android/app/src/main/AndroidManifest.xml`** — add above `<application>`:

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

(No custom string needed on Android — `permission_handler`'s runtime
prompt uses the OS default wording, and Google Play's Data Safety form is
where you separately declare the mic usage — see step 7.)

## 5. RevenueCat setup

1. Create a RevenueCat project, add your iOS and Android apps.
2. In App Store Connect / Google Play Console, create your subscription
   product(s) (see MVP checklist §6 — decide the price/trial length with
   your test agents first; `AppConstants.trialLengthDays` in
   `lib/core/constants.dart` defaults to a 14-day trial as a placeholder).
3. In RevenueCat, create an **entitlement** with the identifier
   `ai_features` (must match `AppConstants.aiFeaturesEntitlementId`
   exactly) and attach your product(s) to it.
4. Create an **offering** named `default` with a package pointing at your
   product — the paywall screen reads `Purchases.getOfferings().current`.
5. RevenueCat dashboard → **Integrations → Webhooks** → add the
   `revenuecatWebhook` Cloud Function URL from step 3, and set the
   `Authorization` header to the same value you stored in
   `REVENUECAT_WEBHOOK_AUTH`.
6. Copy your **public** API keys (separate for iOS and Android) from
   RevenueCat → Project settings → API keys. You'll pass these at run
   time (next step) — they are safe to embed at build time, but this repo
   keeps them out of source via `--dart-define` so you're not tempted to
   hardcode them into a committed file.

## 6. Run the app

```bash
flutter run \
  --dart-define=REVENUECAT_API_KEY_ANDROID=goog_xxx \
  --dart-define=REVENUECAT_API_KEY_IOS=appl_xxx
```

For a real device build, put the same flags into your CI/build scripts,
or into an untracked `--dart-define-from-file=env.json` (see
`flutter run --help` for that flag) so you're not typing them every time.

## 7. Before you submit to the app stores

Straight from the MVP checklist — none of this is automatic:

- [ ] Update `AppConstants.privacyPolicyUrl` and `AppConstants.supportEmail`
      in `lib/core/constants.dart` with real values, and publish a real
      privacy policy (`docs/PRIVACY_POLICY_TEMPLATE.md` is a starting
      draft — have it reviewed, it is **not** legal advice).
- [ ] Fill out Google Play's **Data Safety form** and Apple's
      **App Privacy** section accurately: this app collects voice
      recordings (transient) and contact info (client phone numbers), and
      that must be disclosed even though the *agent's own* account data
      is comparatively minimal.
- [ ] Set an appropriate **age rating** (this is a professional/business
      tool — most stores have a category for that).
- [ ] Confirm empty-state behavior really doesn't crash: fresh install,
      no leads, no recordings — the app should show the empty dashboard
      state, not error out. (Every list-backed screen in this build
      renders `AppEmptyState` instead of a blank list — verify it live on
      a clean install.)
- [ ] Test the account-deletion flow (Settings → Delete account) end to
      end against your deployed Functions — Apple requires this to work,
      not just exist.
- [ ] Test on one real iPhone and one real Android device, not just
      simulators — per the checklist's milestone list.

## Assumptions made while building this

The original requirements doc left a couple of things implicit. These are
reasonable defaults, not decisions — validate them with your wife's agent
network per §7 of the original doc, then adjust:

- **`dealValue` field.** "Commission: percentage + computed value" needs
  a base amount to compute against, which wasn't named as its own field.
  Added as `dealValue` (purchase price, or rental value for rent deals).
  See `docs/DATA_MODEL.md` for the full reasoning — if agents actually
  compute rental commission differently (e.g. multiple of monthly rent
  rather than percent-of-annual), the formula in `Lead.commissionValue`
  (`lib/models/lead.dart`) needs to change, not just this field.
- **14-day trial, no lead cap.** The checklist offered both options
  ("capped at 5 leads, or 14-day full trial") and asked you to decide
  after talking to agents. This build implements the time-based trial
  (`AppConstants.trialLengthDays`) since it doesn't require extra
  UI/logic to enforce a count — swap to a lead-count cap in
  `lib/providers/subscription_provider.dart` if agents prefer that model.
- **Dashboard search is client-side.** With the lead volumes a single
  agent realistically has (tens to low hundreds), filtering the already-
  synced list in `LeadProvider` avoids standing up a separate search
  index (e.g. Algolia) for v1. Revisit if agents end up with thousands of
  leads.
- **Speech-to-text is Google Cloud Speech-to-Text**, not a specific
  vendor named in the checklist (it didn't name one). Recording format is
  16kHz mono LINEAR16 WAV specifically so the Cloud Function can call it
  directly with no transcoding step — see `functions/src/transcribeAudio.ts`.
- **AI cleanup uses Claude** (`claude-opus-4-8`) via the Anthropic API —
  see `functions/src/cleanupTranscript.ts`.

## Project layout

```
lib/
  core/          constants, theme, formatters, env (--dart-define reads)
  models/        Lead, Activity, AppUser — see docs/DATA_MODEL.md
  services/      thin wrappers over Firebase/RevenueCat/record SDKs
  providers/     ChangeNotifier state: auth, leads, activities, subscription
  screens/       auth, dashboard, lead detail/form, subscription, settings
  widgets/       shared empty-state / loading widgets
functions/       Cloud Functions (TypeScript): transcription, AI cleanup,
                 account deletion, RevenueCat webhook
docs/            data model reference, privacy policy template
firestore.rules, firestore.indexes.json, storage.rules, firebase.json
```
